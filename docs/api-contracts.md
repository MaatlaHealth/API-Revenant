# Management API Contracts — `/api/v1`

JSON over HTTP. All routes except `/healthz` and `/readyz` require `Authorization: Bearer <admin token>`. The OpenAPI document generated by FastAPI at `/api/v1/openapi.json` becomes the authoritative reference once Stage 2 is implemented; this file is the design it must satisfy.

## Conventions

- IDs are UUID strings. Timestamps are ISO 8601 UTC.
- List endpoints accept `limit` (default 50, max 200) and `offset`, and return `{ "items": [...], "total": n }`.
- Errors use one envelope:

```json
{ "error": { "code": "validation_failed", "message": "Human-readable summary", "details": [ { "field": "slug", "issue": "already exists" } ] } }
```

| Status | `code` examples |
|---|---|
| 400 | `validation_failed`, `unsupported_evidence`, `unsafe_url` |
| 401 | `unauthenticated` |
| 404 | `not_found` |
| 409 | `conflict`, `stale_reconstruction`, `runtime_not_ready`, `immutable` |
| 413 | `payload_too_large` |
| 422 | `adapter_invalid` (static validation failures listed in `details`) |
| 503 | `database_unavailable`, `not_ready` (the process is in `standby`, `handover` or `superseded` and is not the serving instance) |

Before any route is matched, the host dispatcher may answer `400` (malformed host) or `421` (host is neither a management host nor a registered legacy host); see "Runtime data plane" below. Those responses have a minimal body and no error code from this table.

## Projects

| Method & path | Purpose |
|---|---|
| `POST /projects` | Create. Body: `name`, `slug?`, `description?`, `legacy_name`, `replacement_name`, `replacement_base_url?`. |
| `GET /projects` | List with status, evidence counts, last verification metrics (behavioural compatibility and evidence coverage, each with its denominator), runtime status. |
| `GET /projects/{id}` | Detail, including a `workflow` object stating which steps are complete and what blocks the next one. |
| `PATCH /projects/{id}` | Update name, description, base URL, settings. |

| `GET /projects/{id}/activity` | Recent audit records. |
| `POST /demo/seed` | Create the GravePay → NovaPay demonstration project from bundled files. Idempotent. The project is flagged `is_demo`. |

## Evidence

| Method & path | Purpose |
|---|---|
| `POST /projects/{id}/evidence` | `multipart/form-data`: `file`, `side` (`legacy`/`replacement`), `kind?` (auto-detected when omitted). Returns the evidence record with `parse_status` and `parse_report`. A file that fails to parse returns `201` with `parse_status: "failed"` and reasons — it is stored, not discarded. Unsupported type or oversize returns `400`/`413`. |
| `POST /projects/{id}/evidence/manual` | A manually entered endpoint example (request + response JSON). |
| `GET /projects/{id}/evidence` | List files with parse status. |
| `GET /projects/{id}/evidence/{evidence_id}` | Detail including the parse report and extracted fact counts. |
| `DELETE /projects/{id}/evidence/{evidence_id}` | Remove a file from the current evidence set (soft delete: the row and content are retained for historical runs). Increments the evidence version; existing reconstructions become stale. |
| `GET /projects/{id}/endpoints?side=` | Parsed endpoints with schemas. |
| `GET /projects/{id}/endpoints/{endpoint_id}/facts` | Facts with provenance (`evidence_file`, `locator`, `basis`). |
| `GET /projects/{id}/fixtures` | Imported fixtures with their associated endpoint. |
| `GET /projects/{id}/evidence/missing` | Computed list of missing evidence (e.g. endpoint with no fixture, status code with no example). |

Fixture file format (documented, versioned):

```json
{
  "revenant_fixtures": "1.0",
  "fixtures": [
    {
      "name": "create charge — success",
      "recorded_at": "2025-03-14T09:21:07Z",
      "request":  { "method": "POST", "path": "/v1/charges", "query": {}, "headers": { "X-API-Key": "[REDACTED]" }, "body": { "customer": "C102", "amount": 500, "currency": "ZAR" } },
      "response": { "status": 201, "headers": { "Content-Type": "application/json" }, "body": { "id": "ch_1042", "status": "succeeded" } },
      "variable_fields": ["$.id", "$.created"]
    }
  ]
}
```

A **paired replacement recording** uses the same format, uploaded with `side=replacement`, with one extra key per fixture: `"pair_with": "<name of the legacy fixture>"`. It is evidence of what the replacement returns for the equivalent operation and is the response-side input for offline replay. A `pair_with` that matches no legacy fixture is reported in the parse report.

## Reconstruction and mappings

| Method & path | Purpose |
|---|---|
| `POST /projects/{id}/reconstructions` | Run the analysis synchronously (bounded input sizes). Returns the report summary. |
| `GET /projects/{id}/reconstructions/latest` | Report: endpoint pairs, differences grouped by category, counts by confidence; `evidence_version` analysed; computed `stale` flag with the number of evidence files not yet analysed; `inventory_size`; `inventory_diff` against the previous reconstruction (behaviours added and removed, N before and after). |
| `GET /projects/{id}/reconstructions` | History. Past reconstructions and their inventories are retained and read-only. |
| `GET /projects/{id}/comparison` | Side-by-side contract view per endpoint pair. |
| `GET /projects/{id}/mappings?status=&category=&confidence=` | List mappings. |
| `GET /projects/{id}/mappings/{mapping_id}` | Detail with resolved evidence references. |
| `POST /projects/{id}/mappings/{mapping_id}/approve` | Body: `note?`. |
| `POST /projects/{id}/mappings/{mapping_id}/reject` | Body: `note?`. |
| `PUT /projects/{id}/mappings/{mapping_id}` | Body: `transformation`, `note?`. Validates the rule against the rule models and creates a superseding `origin: human` mapping in status `proposed`, classified `inferred` with no evidence references; it must then be approved. `400` lists every problem. Effect mappings are not edited here. |
| `POST /projects/{id}/mappings/bulk-approve` | Body: `ids` **or** `filter: { confidence: "observed", category? }`, and `note?`. Inferred mappings are never bulk-approved by filter; they must be listed by id. Returns the ids approved and, for `ids`, those skipped with the reason. |
| `GET /projects/{id}/gaps` | Unresolved behaviours. |
| `PATCH /projects/{id}/gaps/{gap_id}` | Set `resolution` (`accepted_risk` with a required note). |
| `GET /projects/{id}/operations` | (`operation_id` is the id of the legacy endpoint.) Every paired operation with its legacy and replacement methods, its declared effect (`read_only`, `state_changing`, `unknown`), the effective effect after the method floor, and who declared it. |
| `PUT /projects/{id}/operations/{operation_id}/effect` | Body: `effect`, `note` (required). Creates an `effect` mapping decision. Declaring `read_only` is rejected with `400` if either method is not `GET`, `HEAD` or `OPTIONS`, or if evidence marks the operation state-changing. Declaring `state_changing` is always accepted. Written to the audit log. Takes effect in the next compiled adapter version. |

Review applies to the latest reconstruction only. A mapping, gap, invariant or behaviour of an earlier reconstruction is read-only: an attempt to decide or change it returns `409 immutable`. Decisions are not carried over to a new reconstruction, because it analysed different evidence. Mapping, gap and invariant lists return the latest reconstruction and accept `limit` and `offset`.

## Verification

| Method & path | Purpose |
|---|---|
| `POST /projects/{id}/verification-runs` | Body: `adapter_version?` (default latest), `layers?` (subset of `offline`, `independent`, `live`; default all), `hypothesis_max_examples?`, `seed?`. Uses the latest reconstruction; refused with `409 stale_reconstruction` if evidence has changed since it. The evidence version, inventory, scopes, configuration and target permissions are snapshotted at this moment. Returns `202` with the run; execution continues in a background task. |
| `GET /projects/{id}/verification-runs` | History. |
| `GET /projects/{id}/verification-runs/{run_id}` | Run summary (below). |
| `GET /projects/{id}/verification-runs/{run_id}/results?outcome=&layer=&category=&traffic_source=&effect=&endpoint_id=&evidence_overlap=` | One row per planned check, with oracle, field-level diffs, ignored-field count and reason for `unresolved` / `skipped` / `error`. |
| `GET /projects/{id}/invariants` | Legacy-only invariants with confidence and evidence. |
| `POST /projects/{id}/invariants/{invariant_id}/approve` · `/reject` | Decide an `inferred` invariant. |
| `PUT /projects/{id}/verification-target` | Body: `base_url`, `label` (e.g. "NovaPay simulator"), the three traffic permissions below, and optional `sandbox_headers` (object of fixed, non-secret header names and values) and `reset_request` (`{ "path": "/…" }`, always `POST`). `base_url` is validated by the outbound guard. Changing a permission writes an audit record. |
| `GET /projects/{id}/verification-target` | Current target and permissions. |

Traffic permissions (all `false` by default):

| Field | Meaning |
|---|---|
| `allow_replay_traffic` | Recorded fixture requests and scripted sequences may be sent. |
| `allow_generated_traffic` | Hypothesis-generated requests may be sent. |
| `allow_state_changing_traffic` | Operations not classified read-only may be exercised, from whichever of the two sources is itself permitted. Applies to all traffic sources; sends nothing on its own. |

| Traffic | Operation effect | Required |
|---|---|---|
| Offline fixture replay | any | none |
| Live recorded / scripted | `read_only` | `allow_replay_traffic` |
| Live recorded / scripted | `state_changing` or `unknown` | `allow_replay_traffic` and `allow_state_changing_traffic` |
| Generated | `read_only` | `allow_generated_traffic` |
| Generated | `state_changing` or `unknown` | `allow_generated_traffic` and `allow_state_changing_traffic` |

Operation effect is one of `read_only`, `state_changing`, `unknown`. `unknown` is treated as state-changing. A request whose legacy or replacement method is not `GET`, `HEAD` or `OPTIONS` is always state-changing, whatever is declared (`architecture.md` §5.4).

`GET /projects/{id}/verification-plan` returns the planned checks with their `traffic_source` (`offline`, `recorded`, `generated`), `effect`, and whether each would run or be skipped under the current permissions and why, so an operator can see what would be sent **before** starting a run.

Rules enforced by the response schema:

- `behavioural_compatibility`, `evidence_coverage`, `behaviour_states`, `provenance`, `state_changing_traffic`, `partially_verified`, `unresolved` and `not_assessed` are all required; a summary cannot be returned with only one metric.
- `state_changing_traffic` is always present, so every report discloses whether state-changing traffic was enabled, what was sent by source and effect, what was blocked, and which operations have an unknown effect. When `enabled` is `false`, every `state_changing` and `unknown` count under `requests_sent` is `0`, and this is asserted when the run is written.
- `behavioural_compatibility` always carries both denominators: behaviours (`behaviours_tested` of `behaviours_total`) and checks (`checks_executed` of `checks_planned_executable`).
- `behaviour_states.total` equals the sum of the five states and equals `behaviours_total`, `evidence_coverage.denominator` and `provenance.inventory_size`.
- `value` is `null` when the metric is undefined (`architecture.md` §6); the API never substitutes 0 or 1.
- Formulas: behavioural compatibility is the weighted per-category pass rate over executed checks, averaged over endpoint groups and the project-level group; `tested_share = (verified + failed) / total`; `evidence_coverage = (verified + failed + not_executed) / total`; `checks_planned_executable = passed + failed + skipped + error`.
- Everything in a completed run's summary is stored and immutable except `provenance.evidence_changed_since_run`, which is computed at read time. There is no endpoint that modifies or recomputes a completed run; an attempt returns `409 immutable`.

`GET /projects/{id}/behaviours` returns the behaviour inventory of the latest reconstruction with each behaviour's state in the latest run on that inventory (or `not_assessed` if there is none). `GET /projects/{id}/reconstructions/{reconstruction_id}/behaviours` returns a past inventory. `PATCH /projects/{id}/behaviours/{behaviour_id}` sets `scope` (`out_of_scope` requires a note); the behaviour stays in the inventory, is reported as not assessed in later runs, and completed runs are unaffected.

A run interrupted by a restart is marked `errored` with reason `interrupted` during startup recovery; it is never left `running`.

## Runtime control

| Method & path | Purpose |
|---|---|
| `GET /projects/{id}/runtime` | Desired state, reported status, adapter version, generation, legacy hosts, path-entry URL, and the full health object (`architecture.md` §4.11) including trace counters, lease state and in-flight request count. |
| `POST /projects/{id}/runtime/start` | Body: `adapter_version?`. `409 runtime_not_ready` (with the specific reason) if no adapter exists, the outbound credential is missing, or inbound auth is declared with no active inbound key. |
| `POST /projects/{id}/runtime/stop` | |
| `PATCH /projects/{id}/runtime` | `legacy_hosts`, upstream timeouts (never above the request lifetime), limits. Each host is normalised with the same function used for dispatch. Rejected with `400`: malformed, wildcard, IP literal, `localhost`, or a management host. Rejected with `409`: already registered, including case, trailing-dot, port and A-label variants. The response returns the normalised form that was stored. |
| `GET /projects/{id}/runtime/events?kind=&outcome=&limit=` | **Persisted** requests, lifecycle and `trace_loss` events. Dropped traces do not appear here; their counts are in the health object. |
| `GET /projects/{id}/runtime/events/{event_id}` | Full redacted transformation trace; `404` if that trace was not persisted. Accepts the `X-Revenant-Request-Id` value. The query string shown is the sanitised one; an inbound query-parameter credential is never present. |

## Credentials

Legacy-client keys and the replacement-provider credential are separate resources. No endpoint returns a stored credential value.

### Legacy-client (inbound) keys

| Method & path | Purpose |
|---|---|
| `GET /projects/{id}/credentials/inbound` | Labels, status, `created_at`, `revoked_at`. |
| `POST /projects/{id}/credentials/inbound` | Body: `label`, `value?`. If `value` is omitted the server generates a key and returns it **once** in this response. Becomes active immediately. |
| `POST /projects/{id}/credentials/inbound/{key_id}/revoke` | Takes effect on the next request. Revoking the last active key while the runtime is running and inbound auth is declared is refused with `409`. |

### Replacement-provider (outbound) credentials

| Method & path | Purpose |
|---|---|
| `GET /projects/{id}/credentials/outbound` | Names, versions, status (`active`, `previous`, `retired`), timestamps. |
| `PUT /projects/{id}/credentials/outbound/{name}` | Body: `value`. Creates a new version, makes it active, demotes the old one to `previous`, and reloads a running adapter atomically. |
| `POST /projects/{id}/credentials/outbound/{name}/rollback` | Re-activates the `previous` version. |
| `POST /projects/{id}/credentials/outbound/{name}/versions/{version}/retire` | Permanently disables a non-active version. |

All credential operations write an audit record containing the actor, label or name, and version — never a value.

## Runtime data plane (not under `/api/v1`)

| Path | Purpose |
|---|---|
| `ANY /runtime/{slug}/<legacy path>` | The legacy interface, path entry. The prefix is stripped; the remainder is the legacy path. |
| `ANY /<legacy path>` with `Host: <legacy host>` | The legacy interface, host entry. Method, raw path, raw query, headers and body reach the runtime exactly as sent (`architecture.md` §4.2). |
| `GET /runtime/{slug}/__revenant/health` · `GET /__revenant/health` on a legacy host | Runtime health (unauthenticated; no credentials or request data). |

Host handling, before any routing (`architecture.md` §4.2):

| Host | Result |
|---|---|
| Malformed (missing, duplicated, bad characters, bad port, non-origin-form target) | `400` |
| Registered legacy host (exact match after normalisation) | Runtime only |
| Management host listed in `REVENANT_PUBLIC_HOSTS` | Management API, and the runtime under `/runtime/{slug}` |
| Anything else | `421`, except `/healthz` and `/readyz` |

On a legacy hostname only the runtime is served: `/api/v1/*`, `/healthz`, `/readyz`, `/runtime/*` and the API documentation are not available there. Forwarded-host headers do not affect this unless explicitly enabled for trusted proxies.

The data plane authenticates with a **legacy-client key**, never the admin token. The legacy key is verified and discarded; it is never sent to the replacement API. When the key is carried in a query parameter, that parameter is removed before the request is processed, traced or logged; all other query parameters are preserved in order (`architecture.md` §4.7).

Every runtime request has a total lifetime limit (default 30 s) covering body upload, the upstream call and the response.

Response headers added by the runtime:

| Header | Value |
|---|---|
| `X-Revenant-Adapter` | Adapter version that served the request. |
| `X-Revenant-Request-Id` | Correlation id. Always present. Not proof that a trace was stored. |
| `X-Revenant-Trace` | `queued` or `dropped` — what happened to the trace at enqueue time. Never "recorded". |
| `X-Revenant-Runtime` | Present on `503`: `stopped`, `failed`, `standby`, `handover` (with `Retry-After`), `lease_expired` or `superseded`. |
| `X-Revenant-Unmapped` | `error` when an upstream error matched no approved rule. |

Runtime status codes generated by API Revenant itself (not by the replacement): `400` malformed host; `401` legacy key missing, wrong or supplied more than once; `404` no route; `408` request body not received within the request lifetime; `421` unexpected host; `500` `credential_leak_blocked`; `502` upstream connection failure or upstream rejected the outbound credential; `503` runtime not serving (stopped, failed, standby, handover, lease expired, superseded), request cancelled because lease ownership was lost, or concurrency cap reached; `504` upstream timeout or request lifetime exceeded during the upstream call. Bodies of these responses contain no request data.
